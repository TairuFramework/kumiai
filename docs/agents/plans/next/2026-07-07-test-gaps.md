# Close test gaps

**Priority:** medium — one guard with teeth, plus a handful of unasserted contracts.
**Origin:** 2026-07-02 audit (commit `bb343d9`), milestone
`archive/2026-07-audit-remediation.md`.
**Re-verified 2026-07-28** against current source. Nine of the original entries had been closed by
later work and were deleted; two carried stale line numbers. Low-priority residue moved to
`backlog/2026-07-28-test-gaps-low.md`. What follows is what survived verification.

## High — worth its own branch

**The app-lane drain's retention guard survives deletion with the whole rpc suite green.**

`app-lane.ts:464`, `if (retentionOf(protocols[name], prc) !== 'log') continue`. (The entry
previously pointed at `peer.ts:1575`; the guard moved to `app-lane.ts` and that line no longer
exists.)

Mutation-verified 2026-07-28: with the line replaced by a comment, `pnpm exec vitest run` in
`packages/rpc` reports **56 files, 374 tests, all passing**.

The guard is the only thing standing between a hostile member and *"make every returning member
re-fire an ephemeral handler out of the log"* — the hazard retention classes exist to prevent.
Retention is the protocol's word, not the frame's, and this is where that is enforced on the replay
path.

Untested because every `retain: 'log'` publish in the suite names an already-logged procedure. A
test has to publish a retained frame naming an **ephemeral** procedure, which no honest dispatch
would ever do — so the test must forge the publish rather than route it through
`surfaceFor().dispatch` (`peer.ts:670`, which chooses the lane by the same retention lookup).

The drain test at `peer-app-drain.test.ts:176` does not reach it: that ephemeral frame rides the
mailbox lane and the fake hub filters it out of `fetchTopic`, so the line is never evaluated.

Write the test by inversion — break the guard first, confirm the new test fails, then restore.

## Medium

- **`CommitRejectedError`'s captured payload is never asserted.** `proposals`, `senderLeafIndex`,
  and the `wrapCommitPolicy` capture path. Every use across `group.test.ts`,
  `groupcontext-extension.test.ts`, and `ledger-bootstrap.test.ts` is `instanceof` or `toThrow`
  only — nothing reads a field off the caught error, so the capture could regress to an empty
  object undetected.
- **`hub-tunnel` teardown contract unasserted.** No test in `packages/hub-tunnel/test/` asserts that
  a `session-end` frame is published, that `hub.unsubscribe` is called, or that `onSessionEnd` fires
  on a peer's frame. `session-end` appears only in `transport-ack.test.ts` and `frame.test.ts`, in
  neither case as the teardown contract. (Companion: `backlog/2026-07-07-hub-tunnel-reliability.md`.)
- **`hub-tunnel-echo.test.ts` still runs against an in-memory double.** Every other file in
  `tests/integration/test/` now drives a real `createHub`; this one builds its transports directly
  (`tests/integration/test/hub-tunnel-echo.test.ts:145,156`) with no hub server, so tunnel-specific
  real-hub semantics remain untested.
- **Peer/handle concurrency, the part still open.** `dispose()` during an in-flight handshake, and
  interleaved `encrypt`/`processMessage` on one `GroupHandle`. `mutex.test.ts` covers the mutex in
  isolation, not the handle that depends on it. (`resync()` racing an inbound Commit and `to()`
  before init are now covered — `peer-resync-serial.test.ts:9`, `peer-to-ready.test.ts:15`.)
  (Companion: `backlog/2026-07-07-rpc-peer-lifecycle-hardening.md`.)
- **Encrypt from a restored handle after an epoch change.** The decrypt half of the original
  persist→restore entry is covered: `tests/integration/test/app-lane-delivery.test.ts:604` restores
  a handle, walks it to `epoch 3n`, and opens frames sealed at epochs it had not reached. What no
  test does is have the *restored* member seal a message after a rotation it walked to. Note the
  integration suite is type-checked by the repo gate but **not run** by it
  (`tests/integration/package.json`), so a test placed there needs a manual run.
