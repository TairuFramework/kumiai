# Milestone: 0.10 band release

**Opened:** 2026-09-25. First planned as a 0.11 milestone following 0.10; folded into 0.10 the same
day, before 0.10 was released, so consumers make one coordinated upgrade instead of two.

## What this milestone is for

0.10 is a `minor` for the `GroupMLS.rosterEntries` break, and durable app-frame delivery changes the
app-frame AAD on the wire. Every package in the band moves together, and every consumer upgrades all
its devices at once. Breaking changes that are ready, or that reshape the same ports, ride this
release instead of the next one.

This follows the standing ruling in `pre-1.0-breaking-api.md`: do not break for its own sake, but when
a package's surface is already breaking for a filed reason, take the neighbours worth taking in the
same `minor`.

## Candidates to decide before the release

Open items from `pre-1.0-breaking-api.md` in packages this release already breaks:

- `processMessage` / `processWelcome` `Uint8Array | unknown` parameter typing
  (`../backlog/2026-07-07-mls-api-hardening.md`). Fits with `applyCommit`.
- A third `GroupPermission` (same doc). No consumer asks for it; leave unless one does.

Record each as taken or left, with the reason, before cutting the release.

### Candidate decisions (2026-09-25)

- **Take input typing in 0.10.** `GroupHandle.processMessage` accepts framed bytes or a decoded
  ts-mls `MlsFramedMessage`. `processWelcome` and `welcomeKeyPackageRefs` accept framed bytes or a
  decoded ts-mls `Welcome`. The prototype changes three signatures without changing runtime paths.
  The forced repo-wide type check found five test diagnostics: four decoded commits needed a
  `mls_public_message` guard, and one malformed-object test needed an explicit unsafe cast.
  Those edits made all 26 type-check tasks pass. Production callers in kumiai pass bytes. Kubun's
  production commit path also passes bytes, but its invite payload declares `welcomeMessage` as
  `unknown`; adoption must validate the decoded payload as `Uint8Array` before joining. Land this
  with the 0.10 port changes and give `mls-rpc`'s exported `applyCommit` a `Uint8Array` commit.
- **Leave a third `GroupPermission` out of 0.10.** No current consumer requests one. The signed
  `kumiai.role` ledger value and folded roster are `admin`/`member`; the envelope guard rejects any
  other value. Kubun's GraphQL enum and app role types also name only those two, while its stored
  role column is already text. A new role needs a defined authority rule and coordinated peer and
  consumer changes, not a speculative union member. Keep MLS membership plus binary admin
  authority. Add narrower application rights through separate ledger claims when a use appears.

## Order

1. Merge durable delivery.
2. Land host handle access on top of it, reshaping `persistOpened` at the same time.
3. Decide the candidates.
4. Run both contract suites against the real implementations and the doubles, and the repo-wide
   type check.
5. Check the pending changesets together: one `minor` per package, with a migration section per port.
